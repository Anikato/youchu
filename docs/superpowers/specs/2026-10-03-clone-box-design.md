# 有处：克隆盒子

日期：2026-10-03

状态：已按用户确认写成（克隆移动容器；前两位类型不动，后面序号加 1；点完留在原页。添加物品不选位置已有，不改）。待实现。

依据：物品和位置规格。冲突时，位置类型、编号唯一、Origin/会话/错误顺序以该规格为准；本文件只覆盖克隆。

## 1. 目标

在移动容器（盒子）页一键再做一个空盒子：名称、父级、图标相同；编号把类型留下、序号加 1。点完仍停在原来的盒子，方便连续克隆。新盒子没有物品、没有下级。

添加物品本来就可以不选存放位置，保存后是「待定位」。本段不改物品接口和表单。

## 2. 不做的事

不克隆区域、不克隆固定储物位。不复制物品或下级位置。不改编号命名空间，程序仍把编号当字符串，只在克隆时按下面规则算出下一个。不加确认框。不改 Origin、会话、环境变量。Playwright 不进仓库。没有新表。

## 3. 编号

编号按 Unicode 码点计。前两个码点是类型，后面整段是序号（十进制数字，可含前导零）。

- `B102`：类型 `B1`，序号 `02` → 下一个 `B103`
- `B109` → `B110`
- `B112` → `B113`
- `B199` → `B1100`（序号从 99 到 100，位数变长）
- 编号不能含空白，界面上的「B1 02」存成 `B102`

下一个编号已被占用则继续加 1，直到空号。最多试 10000 次。源编号少于 3 个码点、后面不是纯数字、加完超过 32 个码点、或试满仍无空号：`invalid_fields`，`fields.code` 为「编号无法递增」或「编号过长」（超过 32 时用「编号过长」）。

## 4. HTTP

`POST /api/v1/locations/{id}/clone`

201，正文是新位置对象，与创建位置相同。源位置 `version` 不变。

写路由失败顺序与位置写接口相同：Origin 403 → 会话 401 → 正文/查询 → 路径 id 存在（404）。查询参数拒绝。正文可空或 JSON 对象（含 `{}`）；不是对象则 `invalid_body`。路径 id 在 Origin、会话和正文/查询之后才解析。

源不是移动容器：400 `invalid_fields`，`fields.type` 为「只有移动容器可以克隆」。源不存在：404。新盒子用现有创建规则写入（父级仍须合法）。

其它方法打到 `/clone` 返回 404。

## 5. MCP

`youchu_clone_location`，参数 `id`，需要 `write`。行为与 HTTP 相同。

## 6. 网页

仅移动容器详情页显示「克隆」。成功后不跳转，提示「已克隆为 {新编号}」。保存按钮旁即可。390 宽无横滑。

## 7. 测试

- `NextBoxCode`：`B102`→`B103`，`B199`→`B1100`，`B1` 失败。
- 克隆 `B101` 得 `B102`，名称父级相同，源 `version` 仍为 1，新盒子 `direct_item_count` 为 0。
- `B102` 已存在时克隆 `B101` 得 `B103`。
- 区域或固定储物位 400。Origin 错误 403 先于无会话 401 和无 id 404。
