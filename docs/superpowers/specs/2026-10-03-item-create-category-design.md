# 有处：添加物品时新建分类

日期：2026-10-03

状态：已实现。方案 A：物品表单只填名称，一律建成根分类；之后可在分类页改成子分类，物品关联不受影响。

依据：分类和搜索规格。冲突时，分类树、同级重名、Origin/会话、物品分类关联以该规格为准；本文件只覆盖物品表单上的新建入口。

## 1. 目标

在添加或编辑物品时，分类栏可以直接填名称新建一个分类，立刻挂到当前这件物品的草稿上。新建出来的一律是根分类。不必先去分类页。

之后在分类详情页改父级，把它变成某个分类的子分类。物品上的 `category_id` 不变；路径按新父链现算。按父级筛选（默认含下级）仍能找到这件物品。

## 2. 不做的事

物品表单上不选父级。不一次建整棵树。不改分类 API、表、MCP。不改分类页的新增/改父级。不自动保存物品。Playwright 不进仓库。没有新表、没有新环境变量。

## 3. 网页

`ItemCategoriesField`（`/items/new` 和 `/items/:id` 共用）在现有「选择分类 / 添加」下面增加「新建分类」：名称输入和「新建」按钮。

- 调用已有 `POST /api/v1/categories`，正文只有 `name`（省略 `parent_id`，即为根）。
- 成功后把返回对象加入当前物品的分类草稿，刷新分类列表缓存，停在本页。物品要等用户点「保存」才写入关联。
- 「新建」是 `type="button"`。名称框里按 Enter 只触发新建，不提交物品表单。
- 名称为空时按钮不可用。重名根分类：409 `name_taken`，提示「同级已有相同名称」，草稿不变。
- 390 宽无横滑。

## 4. 改成子分类

已有行为，本段用测试钉住，不改代码：

- `PATCH /api/v1/categories/{id}` 带 `parent_id` 只改这一行。
- 不改 `item_categories`，不改物品 `version`。
- 子分类仍指向它。读取时 `path` 现算。
- 同级重名仍是 409 `name_taken`；移到自己的下级仍是 409 `category_cycle`。

## 5. 测试

- 根分类挂到物品后改父级：物品 `category_id` 不变，`path` 变成「父 / 自己」，按父级查（含下级）能找到，仅当前父级则找不到。
- `cd web && npm run build`。
- 浏览器：添加物品页填名称、新建分类，分类出现在草稿里；保存后到分类页改父级，物品路径跟着变。
