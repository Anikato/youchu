# 有处：添加物品时搜索位置

日期：2026-10-03

状态：已实现。

依据：添加物品体验规格把「位置下拉改成可搜索」留到下一刀。冲突时，上次位置、保存后留在新增页、手机贴底保存仍按那份规格。

## 1. 目标

盒子多的时候，在新增或编辑物品里用名称或编号把位置筛出来，点一下就加上。

## 2. 不做的事

不改 `GET /api/v1/locations`。不改分类选择器。不改位置页的父级下拉、物品列表的位置筛选。不做按分类排序。不在浏览器里压缩照片。没有新表、没有新环境变量、没有新 npm。Playwright 不进仓库。

## 3. 行为

只改物品表单的「存放位置」（新增页和编辑页共用的 `ItemLocationsField`）。

已选位置仍显示路径、放置说明、移除。下面不再用 `<select>` 加「添加」。改成：

- 搜索框，`name="location_q"`，placeholder「找位置」。
- 焦点在框里、或框里有字时，列出尚未选中的位置。空查询列出全部未选。
- 匹配名称、编号、路径上每一级的名称和编号，以及页面上那条路径文案（`名称 编号` 用 ` / ` 连接）。英文大小写无关，中文按子串。查询先去掉首尾空白。
- 点一条立刻加入，不必再点添加。加入后清空查询，列表仍开着（方便连加）。
- 回车加入当前列表第一条；没有符合的条目时回车不提交物品表单。Escape 收起列表。
- 没有符合时显示「没有符合的位置」。
- 点框外收起列表。点列表项时用 mousedown 阻止失焦，避免点不到。
- 列表最高约 12rem，内部滚动。路径文案可换行。宽度 390 不出现横向滚动。

上次使用的位置、地址栏 `location=` 预填不变。物品仍可不选位置。

## 4. 测试

- `filterLocations`：空查询原样返回；编号大小写无关；名称子串；路径上级能命中；去空白；没有符合时为空。
- `cd web && npm run build`。
- 浏览器：新增页输入某个盒子的编号，列表只剩它，点选后出现在已选里，搜索框清空；390 宽无横滑。
