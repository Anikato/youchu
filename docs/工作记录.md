## 已经落地的行为

- Go 模块 `youchu`。入口是 `cmd/youchu`。网页在 `web/`，开发时由 Vite 提供，`/api` 和 `/mcp` 代理到 Go。生产把 Vite `dist` 嵌入 `internal/webui`；仓库里的 `dist` 只有占位，本机 `go run` 的 `GET /` 仍是 JSON 404。
- 启动顺序：校验配置、检查嵌入迁移编号、打开数据库、执行迁移、创建 `originals/`、`thumbnails/`、`tmp/`、用户表为空时创建唯一账号、监听。目录创建失败则不监听。
- 数据库是 `YOUCHU_DATA_DIR/youchu.db`，默认 `./data/youchu.db`。DSN 固定带 `_foreign_keys=on`、`_busy_timeout=5000`、`_journal_mode=WAL`，作用在每条新连接上。`SetMaxOpenConns(4)`。
- 迁移在 `migrations/`，经 `go:embed` 载入。嵌入版本必须从 `001` 连续到 `008`。已执行版本必须是连续前缀，只跑剩余部分。数据库版本更高，或前缀不连续时，拒绝启动且不改已有迁移行。`007` 给 `locations` 加可空 `icon`。`008` 建 `location_icons`，给 `locations` 加可空 `custom_icon_id`。
- 唯一用户 `users.id = 1`。首次创建读 `YOUCHU_USERNAME` 和 `YOUCHU_PASSWORD`，argon2id，参数 memory 64 MiB、iterations 3、parallelism 4。已有用户时忽略这两个变量，不重置密码。
- 会话 Cookie 名 `youchu_session`。库里只存 SHA-256。默认 14 天，不滑动续期。可同时有多条会话。
- 接口：`POST /api/v1/session`、`DELETE /api/v1/session`、`GET /api/v1/me`、`PATCH /api/v1/me`、`POST /api/v1/me/password`、`GET|POST /api/v1/tokens`、`DELETE /api/v1/tokens/{id}`、`POST /mcp`。网页写请求的 `Origin` 必须等于 `YOUCHU_PUBLIC_ORIGIN`。登录按地址固定窗口限流，默认每 60 秒 10 次。`YOUCHU_TRUST_PROXY` 默认 `false`，不读 `X-Forwarded-For`；为 `true` 时取该头最左一段。开发时 Vite 代理会导致各浏览器共用一个桶，这是第一阶段接受的行为。
- `PATCH /api/v1/me` 只认 `username`。成功 200，规范化后写入 `users.username` 和 `users.updated_at`，现有会话全部保留。旧用户名登录仍是 `invalid_credentials`。
- `POST /api/v1/me/password` 只认 `current_password` 和 `new_password`。成功 204，argon2id 参数与建号相同；同一事务里删掉当前 Cookie 以外的会话，当前会话继续有效。不计入登录限流，不改 Cookie。
- 网页是家用纸色目录：`web/src/theme.css` 变量，CSS Modules，中文。默认 `html[data-theme=dark][data-accent=moss]`。账号页「外观」可切浅色和苔绿/陶土/墨蓝，立刻写入 `localStorage`，刷新仍在。不跟系统外观，不同步到别的浏览器。登录页标题「有处」，说明「家里的东西在哪儿」。登录后页头：左上标志和「有处」回物品列表；主入口物品 / 位置 / 分类 / 待归位；用户名进 `/account`。页头没有回收站，没有退出。路径 `/account`、`/returns`、`/trash`、`/trash/:id`。
- 账号页可改外观、用户名、改密码、签发接入令牌、进回收站、退出。没有注销账号。明文令牌只在创建成功时出现一次；列表只有 `token_prefix`；可撤销。打开账号页时「读取」和「归类」勾选，「写入」不勾选；「读取」不能取消。
- 位置 JSON 有 `icon`（`null` 或允许清单短名）和 `custom_icon_id`（`null` 或库 id）。路径节点同样。两者不能同时非空。MCP 与 HTTP 相同。未选图标时界面按类型用房子/柜子/盒子。自传 SVG 从库里按 id 画。位置和分类列表按 `path.length` 缩进，子级左侧浅线。位置行：图标、名称、编号徽章、直接件数。选择器选项用全角空格表示层级。
- 账号页「图标」和位置表单「我的」写入同一份库。`GET/POST /api/v1/location-icons`，`GET/PATCH/DELETE /api/v1/location-icons/{id}`。在用则删除 409 `icon_in_use`。MCP 有 `youchu_list_location_icons`、`youchu_create_location_icon`、`youchu_update_location_icon`、`youchu_delete_location_icon`。创建/更新位置工具接受 `icon` 与 `custom_icon_id`。
- 接入令牌哈希存在 `access_tokens`。范围只能是 `read`，以及可选的 `organize`、`write`。必有 `read`。最多 20 张。MCP 用 `Authorization: Bearer` 访问 `http://127.0.0.1:8080/mcp`；开发时 `http://127.0.0.1:5173/mcp` 由 Vite 转发。Cookie 会话不能当 `/mcp` 凭证。不要用 `localhost`（Origin 必须是 `http://127.0.0.1:5173`）。
- MCP 工具直接调 `internal/catalog`，不向本进程发 HTTP。只读 12 个、归类 3 个、写入 13 个。没有 `youchu_purge_item`、`youchu_delete_location`、`youchu_delete_category`、`youchu_upload_photo`、`youchu_delete_photo`、`youchu_set_photo_first`。归类只追加 `source=ai`，不能去掉 `human`。创建/更新物品工具没有 `categories` 字段。
- 物品列表最上是查找，placeholder 和 aria-label 都是「找家里的东西」，同一行「新增」。默认按添加时间新到旧（`created_at DESC, id DESC`），可选「按名称」（`sort=name`，`ORDER BY name, id`）。卡片显示相对添加时间。物品表单顺序：名称 → 存放位置 → 分类 → 「更多说明」（别名到备注）→ 拍照/相册 → 保存。存放位置用 `name="location_q"` 的「找位置」过滤已加载扁平列表（名称、编号、路径），点一条即加入，回车加入第一条；位置页父级和物品列表筛选仍是下拉。分类栏可选择已有分类，也可填名称「新建」成根分类并立刻挂到草稿；物品保存后才写入关联。之后可在分类页改父级，物品 `category_id` 不变。新增页「更多说明」默认收起。新建页待传照片显示缩略图，可单张去掉；保存物品后再 `POST /api/v1/items/{id}/photos`。保存成功（含照片失败）留在 `/items/new`，清空名称和待传照片，保留位置和分类，提示「已保存：{名称}」链到该物品；部分照片失败时加「有照片没传上」。上次位置、分类写入 `localStorage`（`youchu-last-location-id`、`youchu-last-category-ids`）；地址带 `location`/`category` 时用地址。名称非空或还有待传照片时离开先问「尚未保存，要离开吗？」。宽度 ≤640px 主保存贴在底栏上方。编辑页保存成功留在本页，提示「已保存」。`useBlocker` 需要数据路由，入口是 `createBrowserRouter`。移到回收站在页尾。
- 物品普通删除确认文案是「将移到回收站」，成功后进回收站，位置、分类、归位事项都保留。永久删除只在回收站里再次确认，文案「永久删除，无法恢复」。空位置和空分类的删除仍是物理删除，确认文案仍是「永久删除，无法恢复」。
- 位置和分类对象带 `direct_item_count`（含回收站物品，不含下级）。当前范围没有正常物品、但回收站里仍占用时，显示「回收站里还有物品占用这个位置/分类」，并且不显示删除。
- 物品版本冲突时保留未保存的名称、备注、位置选择和分类选择，要点「加载最新内容」才改成服务器上的记录。物品保存 404 显示「未找到」并回到物品列表。
- 归位事项不记位置 id、不记分类 id。新增、完成、去掉事项不改物品的 `version`、`updated_at`、存放位置和分类。完成一条只关闭该条。事项 404 时若物品仍在，只刷新事项区并提示「该事项已不存在」，未保存的物品字段和新事项草稿保持原样，不离开物品页。
- 待归位清单和回收站列表每页 30 条。删掉或完成末页最后一行后会把 `offset` 夹到仍有行的一页，不会停在空白页。
- 物品列表筛选用 `web/src/filters.ts` 的 `writeItemList`。清空或改筛选会丢掉依附参数：分类从两个减到一个时去掉 `category_match`；清空分类或改成未分类时去掉 `category`、`category_match`、`category_descendants`；清空位置或改成待定位时去掉 `in_location`、`in_location_descendants`。默认不写 `sort`；选「按名称」时写 `sort=name`。改排序会去掉 `offset`。`GET /api/v1/items` 与 MCP `youchu_search_items` 的 `sort` 只接受省略、`created_at` 或 `name`，出现两次或其他值是 `fields.sort`「不支持的参数」。回收站列表顺序不变。
- 分类页切「仅当前分类」会删掉 `items`，保留已有的 `children`。
- 根分类同级重名用两条部分唯一索引，不是 `UNIQUE(parent_id, name)`。创建、改名或移到同级已有名称时 409 `name_taken`。
- 分类选择器和物品列表筛选会按页取完整棵分类树。根分类列表分页能翻到「分类-101」（预先建「分类-001」到「分类-101」）。
- 照片入口是「拍照」（`capture="environment"`，单张）和「相册」（可多选）。`FileList` 是活引用，清空 input 之前要先拷成数组，否则加不上照片。物品页照片区在保存/删除下面、待归位上面。一次选出的多张按顺序各发一次 `POST`。
- Safari 加到主屏幕：`web/public/manifest.json` `display: standalone`，`apple-touch-icon.png`，`apple-mobile-web-app-capable`。没有 Service Worker。切外观时 `theme-color` 跟 `--paper`（深 `#161a18`，浅 `#f3f6f4`）。
- 网页动效用 `gsap` 与 `@gsap/react` 的 `useGSAP`：登录面板、换页主内容、物品/位置列表第一次画出 stagger 0.03s。属性只有 `autoAlpha` 和 `y`，约 0.35s `power2.out`。`prefers-reduced-motion: reduce` 时时长为 0。没有 ScrollTrigger。
- 一件最多 20 张。新照片排在末尾。设为第一张后，物品列表、位置页、分类页、待归位物品名链接、回收站列表都用这一张缩略图。加、删、设第一张不改物品 `version` / `updated_at`。
- 物品 JSON 必有 `photos` 数组（没有时是 `[]` 不是 `null`）。归位事项必有 `cover_photo`（没有时原文 `"cover_photo":null`）。PATCH 物品带 `photos` 会忽略。分类关联必有 `source`（`human` 或 `ai`）。网页保存仍把提交的集合写成人工关联。
