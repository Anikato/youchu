## 5. MCP 怎么接

MCP 是 Streamable HTTP，服务名 `youchu`，版本 `0.1.0`，无状态。`/mcp` 只认 `Authorization: Bearer` 加上完整令牌。网页登录用 Cookie `youchu_session`。

### 5.1 签发令牌

1. 登录网页 → 账号 → 「接入令牌」
2. 填名称，勾选范围。打开页面时「读取」和「归类」已勾，「写入」未勾。「读取」不能取消。
3. 创建成功后立刻复制完整令牌（`yc_` 加一段 URL-safe Base64）。刷新后只剩前 12 个字符的 `token_prefix`。
4. 最多 20 张未撤销令牌。撤销是删除行，立刻失效。改密码、改用户名、退出网页会话都不撤销令牌。

| 范围 | 能做的事 |
| --- | --- |
| `read` | 查物品、位置、分类、待归位、回收站；读照片 JPEG 字节 |
| `organize` | 新建分类；给物品追加 AI 分类；去掉该物品上的 AI 分类 |
| `write` | 新建/编辑物品和位置；克隆移动容器；编辑分类名称或父级；物品进回收站/恢复；待归位的新建/完成/去掉；位置图标库 |

每张令牌必须包含 `read`。库里存的是规范化逗号串，只能是：`read`、`read,organize`、`read,write`、`read,organize,write`。

助手改数据、归类、放入回收站，必须是用户刚刚明确要求的操作。归类只增加 `source=ai` 的关联，去不掉网页写下的人工分类。

下列操作只有网页能做，MCP 没有对应工具：永久删除物品、删除位置、删除分类、改用户名、改密码、签发/撤销令牌、上传/删除/设封面照片。

### 5.2 接到 Grok

令牌写入权限 `600` 的文件，例如 `~/.config/youchu/mcp.token`（一行，完整 `yc_…`）。

```bash
grok mcp add --transport http youchu https://yc.hiny.cn/mcp
```

然后在当前 Grok 使用的配置里写成文件令牌（有的安装用 `~/.grok/config.toml`，有的会话 `GROK_HOME` 是 `~/.grok-1`，以 `grok inspect` 为准）：

```toml
[mcp_servers.youchu]
url = "https://yc.hiny.cn/mcp"
enabled = true
bearer_token_file = "~/.config/youchu/mcp.token"
```

也可用环境变量展开，避免把令牌写进配置：

```toml
[mcp_servers.youchu]
url = "https://yc.hiny.cn/mcp"
headers = { "Authorization" = "Bearer ${YOUCHU_MCP_TOKEN}" }
```

检查：

```bash
grok mcp doctor youchu
```

握手成功时应能列出约 29 个 `youchu_*` 工具。新加的服务器要开一个新会话才会进工具目录。Grok 里调用名是 `youchu__youchu_search_items` 这种 `服务器名__工具名`。

开发时也可以指向本机：`http://127.0.0.1:8080/mcp`（Go 进程）或 `http://127.0.0.1:5173/mcp`（Vite 转发）。两边都要带同一个 Bearer。

### 5.4 用 HTTP 自测

客户端 `Accept` 同时带 `application/json` 和 `text/event-stream`。协议版本 `2025-11-25`。无状态模式下 initialize 常常没有 session id，随后的 `tools/call` 仍可直接 POST。响应经常是 SSE 的 `data:` 行。

```bash
export YOUCHU_MCP_TOKEN='yc_…'   # 从账号页复制，不要提交

curl -sS https://yc.hiny.cn/mcp \
  -H "Authorization: Bearer $YOUCHU_MCP_TOKEN" \
  -H "Accept: application/json, text/event-stream" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-11-25","capabilities":{},"clientInfo":{"name":"handoff","version":"0.1"}}}'

curl -sS https://yc.hiny.cn/mcp \
  -H "Authorization: Bearer $YOUCHU_MCP_TOKEN" \
  -H "Accept: application/json, text/event-stream" \
  -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/call","params":{"name":"youchu_list_locations","arguments":{"flat":1,"limit":100}}}'
```

`flat` 必须是整数 `1`（JSON 里写 `1`，写成 `true` 会失败）。

认证失败是 HTTP 401 JSON `unauthenticated`，带 `WWW-Authenticate: Bearer realm="youchu"`。范围不够是工具错误 `forbidden`（「当前令牌没有这项权限」），仍是 JSON-RPC 成功外壳。业务错误形状与网页相同：`code`、`message`，需要时有 `fields`。

## 9. 目录里的东西怎么理解

位置三类：

| 类型 | 父级 | 编号 |
| --- | --- | --- |
| `area` 区域 | 可空，只能是区域 | 无编号 |
| `fixed` 固定格 | 必填，区域或固定格 | 全屋唯一，必填 |
| `movable` 可移动容器 | 可空，固定格或容器 | 全屋唯一，必填 |

编号 1–32 字符，不能有空白，大小写敏感，`001` 与 `01` 不同。固定格和盒子共用一个编号空间。袋子不编号。

家里习惯写法（操作者手填，程序不解析字母含义）：

- 柜子格子：区域字母 + 柜号 + 格号，例如 `K101`
- 盒子：`B` + 型号 + 序号，例如 `B101`、`B201`
- 盒内抽屉/层：另起字母，例如 `D101`、`L101`，避免和盒子序号撞车

克隆移动容器：`POST /api/v1/locations/{id}/clone` 或 `youchu_clone_location`。复制名称、父级、图标；新盒子是空的；编号在同一系列上取下一个空号。

物品可以没有位置（待定位）。一件可以挂多个位置。普通删除进回收站（`deleted_at`），位置和分类还在。永久删除只在回收站里再次确认。空位置、空分类的删除是物理删除；有子位置或仍被物品占用（含回收站占用）则 409。

分类是树。MCP 归类写入 `source=ai`；网页保存写入 `source=human`。网页整表替换分类时会清掉未提交的 AI 关联。

列表多选（2026-10-04）：点「选择」后勾当前页。物品可进回收站或搬家（搬家清掉原位置）。空位置可删，约 10 秒内可撤销（位置撤销是按快照再 POST，id 会变）。占用中的位置勾不了。没有批量 HTTP 路径，客户端按现有接口一条一条发。

位置首页目前只列出根区域和尚未放入的容器，要找柜子里的盒子需要一层层点进去。添加/编辑物品时的「找位置」可以按名称或编号筛已加载的扁平列表。整棵位置树浏览还没有做成单独一页。
